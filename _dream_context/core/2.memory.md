- **★★★ A version stamp is a LOWER BOUND — migrate before you stamp (2026-08-01)**: `setupVersion` opens the runner's half-open range, so stamping first makes the NEXT run compute an empty range and apply nothing, permanently — and the safety valve is blind, since `unfinishedAgentTasks` needs a ledger entry, so an empty ledger reads as a FRESH vault. One helper owns capture→migrate→stamp, the stamp persists only on a clean run, and a SOURCE TRIPWIRE guards the class, not the call sites. Source: file:src/lib/migrate-and-stamp.ts.

- **★★★ Pathspec commits in a shared checkout (2026-08-27)**: two agent sessions in one checkout corrupt each other's commits — session A stages files, B's `git add` replaces the index between A's add and commit, so A's message lands on B's work. The fix: `git commit -F - -- <paths>` — a pathspec commit takes working-tree content for those paths and cannot be poisoned by another process's index. Verify a commit from `git archive HEAD` into a temp dir (node_modules symlinked), not stash/checkout — any tree mutation clobbers the other session's edits. See bookmark bm_wPFL67Qe for the full pattern.

- **★★ Component reuse over reimplementation (2026-08-26, owner correction "atomic çalışsana")**: when a new surface needs a chat-shaped thing, MOUNT THE CHAT'S OWN COMPONENTS on a different session object. The session is the parameter; the components are not. A hand-rolled composer silently costs the slash menu, attachments, model/effort/mode triggers, steer-into-the-running-turn, the queue and drafts, and drifts the moment the real one changes. Source: the peer-mail panel initially rebuilt a textarea+Send composer, an Allow/Deny pair, and a raw-text transcript — while Composer, PermissionCard and ItemView already existed. Rewritten to mount those three on the peer's session object. Generalises: when an existing atomic component fits the need, mounting it is cheaper, more complete, and stays current.

- **★★ Presence assertions pass on invisible elements — assert geometry (2026-08-26)**: a DOM presence check (element exists, :visible, text queryable) passes on an element rendered INVISIBLY. The peer panel rendered inside the docked strip with position:absolute/inset:0, so it resolved against a ~40px box — in the DOM, ':visible', text queryable, and nothing on screen. The screenshot caught it; the test did not. Fix: assert GEOMETRY (boundingBox) for anything that must be seen. Playwright's toBeVisible() checks computed visibility, not layout — it passed while the element was off-screen. Source: scripts/verify/peer-mail-ui.mjs §6a.

## Known Issues


- **Full suite on a saturated machine times out (2026-07-27, recurring)**: under high CPU load `npm test` fails ~11/135 integration tests at the 5s limit — they spawn the CLI and the spawn alone exceeds the window. Run the suite alone.

- **`releases add --yes` over-sweeps (2026-07-07, recurring)**: auto-discovery sweeps far more tasks/changelog/features than belong — v0.13.1 swept 105 tasks for a 2-feature patch. Avoid `--yes`, or trim manually after each add.
