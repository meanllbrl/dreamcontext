## Technical Decisions

> Archived to knowledge/archive/2.memory-2026-h2.md: 62 decisions, 2026-05-23 → 2026-08-01. Findable via `dreamcontext memory recall`.

- **★★★ Soul is constitution-only; enforcement is systemic, not render-time (2026-07-30)**: soul = always-valid rules + agent behavior/voice, rendered FULL and VERBATIM with no rungs (a big soul is correctly big). Everything CONDITIONAL moves to `knowledge/patterns/`, which own a hard-banner block at every rung. Enforced by a char ceiling + the 0.23.0 soul-split migration, NOT by compressing at render. Supersedes "budget ladder unwinnable on mature vaults" (2026-07-28) — the ladder was never the fix. Proof: soul 32,912→3,983; that vault 53,668→16,320, inline, no banner.

- **★★★ Level-0 density doctrine + accounting (2026-07-30)**: the DEFAULT render must itself be compact — never fix at the rungs what level 0 should not have emitted. Only PINNED knowledge carries descriptions at any level; the rest is named, never summarized. A rung ending in a bare count is a BLINDING (supersedes 2026-07-28 bare-count): every inventory section owes an ACCOUNTING — detailed + named + counted = total — plus a search footer at every rung, floors included.

- **★★★ A version stamp is a LOWER BOUND — migrate before you stamp (2026-08-01)**: `setupVersion` opens the runner's half-open range, so stamping first makes the NEXT run compute an empty range and apply nothing, permanently — and the safety valve is blind, since `unfinishedAgentTasks` needs a ledger entry, so an empty ledger reads as a FRESH vault. One helper owns capture→migrate→stamp, the stamp persists only on a clean run, and a SOURCE TRIPWIRE guards the class, not the call sites. Source: file:src/lib/migrate-and-stamp.ts.

- **★★ A hand-mirrored constant needs a text-parsing tripwire (2026-08-01)**: the dashboard copies the debt thresholds (separate Vite package, no import path into `src/`) and drifted through both rescales — "Must Sleep 33/20" while the CLI said "Drowsy 33/60". A file outside your tsconfig can still be parsed AS TEXT in a test and asserted against the real constant. Corollary (`e50935c`): a warning's stated REASON is load-bearing — doctor's wrong one drove a plan to gut the wrong files.

- **★★ The brain stays IN the code repo; git-worktree split-brain is fixed at the resolver (2026-08-01)**: `resolveContextRoot()` walks up from cwd to the first `_dream_context/`, unaware of worktrees — so a worktree gets its own copy of tracked `core/`+`knowledge/`, while gitignored `state/` stays in the main tree (split-brain). Fix is NOT separating brain from codebase (kills `brain-repo.ts:12` invariant, breaks team sync, hard-fails sibling worktrees). Fix is at the RESOLVER: make it worktree-aware via `git rev-parse --git-common-dir` → every worktree resolves to main tree's `_dream_context/`. Source: knowledge:worktrees-and-the-brain, session:76e8e8bb.



## Known Issues


- **Full suite on a saturated machine times out (2026-07-27, recurring)**: under high CPU load `npm test` fails ~11/135 integration tests at the 5s limit — they spawn the CLI and the spawn alone exceeds the window. Run the suite alone.

- **RELEASES.json indent drift → 1000s-line diffs (2026-07-25, ★★ recurring)**: a 1-space rewrite instead of the CLI's 2-space turned a 3-line change into a 6,700-line diff. Match 2-space; never reformat with other tooling.

- **`releases add --yes` over-sweeps (2026-07-07, recurring)**: auto-discovery sweeps far more tasks/changelog/features than belong — v0.13.1 swept 105 tasks for a 2-feature patch. Avoid `--yes`, or trim manually after each add.
