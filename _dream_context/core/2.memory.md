> Archived (findable via `dreamcontext memory recall`): 2.memory-2026-h2.md (63 decisions 2026-05-23→08-18; hand-mirrored constants + worktree resolver 08-01; designed-capability-unwired 08-14), 2.memory-2026-08.md (Level-0 density doctrine 07-30), 2.memory-2026-08-b.md (version stamp LOWER BOUND 08-01).

- **★★★ Verification that assumes preconditions (2026-08-28, third observation)**: a harness that asserts environment state as fact rather than checking it reports success on wrong inputs. The build-and-propagate pattern assumed "global CLI is npm-linked" and propagated published docs (0.26.2) over new ones, green throughout. The tell: "Setup version: 0.26.2" ≠ package.json. CHECK preconditions explicitly; fail loud when they don't hold. Source: knowledge/patterns/build-and-propagate-pattern.md.

- **★★★ Pathspec commits in a shared checkout (2026-08-27)**: two agent sessions in one checkout corrupt each other's commits — session A stages files, B's `git add` replaces the index between A's add and commit, so A's message lands on B's work. The fix: `git commit -F - -- <paths>` — a pathspec commit takes working-tree content for those paths and cannot be poisoned by another process's index. Verify a commit from `git archive HEAD` into a temp dir with BOTH root and `dashboard/node_modules` symlinked (2026-08-29: root-only failed a suite on a missing `marked`; both -> 10/10 green), not stash/checkout — any tree mutation clobbers the other session's edits. See bookmark bm_wPFL67Qe for the full pattern.

> Archived to knowledge/archive/2.memory-2026-09.md: Component reuse over reimplementation (2026-08-26); Presence assertions pass on invisible elements (2026-08-26).

- **★★ Validate the measuring instrument before trusting its verdict (2026-09-05)**: OpenUI Wave 6's scorecard said "33% blank render, 3 fabrications" against a model that actually scored 6/6 and 4/4 — all three failures were harness bugs (no `document` in node, no canvas in jsdom, a regex matching inside quotes), not model bugs. An instrument's own limits silently become the measured thing's faults; verify the harness before trusting a verdict that contradicts a manual spot-check.

- **★★ The parent is the wire — map onto what a remote has, don't ask it to grow (2026-09-06)**: declarable task statuses first let a status bind its own remote status — ClickUp's API can't create one, so it warned and asked the user to fix it by hand. Owner rejected that: declared statuses live UNDER one of the shipped four (a `parent`); the remote sees only the parent, the child rides as a `dc:<key>` label/tag. A failure mode disappeared instead of being documented. Generalizes: when a remote can't express your model, map onto what it has and carry the extra bit in a channel it tolerates (as `version:<v>` already does on ClickUp). Source: src/lib/task-backend/status-mapping.ts.

## Known Issues


- **Full suite on a saturated machine times out (2026-07-27, recurring)**: under high CPU load `npm test` fails ~11/135 integration tests at the 5s limit — they spawn the CLI and the spawn alone exceeds the window. Run the suite alone.

- **`releases add --yes` over-sweeps (2026-07-07, recurring)**: auto-discovery sweeps far more tasks/changelog/features than belong — v0.13.1 swept 105 tasks for a 2-feature patch. Avoid `--yes`, or trim manually after each add.
