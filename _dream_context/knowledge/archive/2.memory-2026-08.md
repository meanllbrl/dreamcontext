## Technical Decisions (Archived)

- **Desktop app bundled CLI + login-shell resolution verified clear (2026-08-26)**: two previously-recorded scars re-checked this cycle and are now CLEAR: (1) bundled CLI reports correct version (0.26.0; was 0.0.0 sentinel on 2026-08-02), (2) login-shell CLI lookup resolves correctly (/usr/local/bin/dreamcontext → nvm → repo dist). - **Dev-link vs npm upgrade on this checkout (2026-08-26, recurring)**: the global `dreamcontext` is an npm LINK to THIS checkout, so `npm run build` IS the install on this machine. `dreamcontext upgrade` must NOT be used here — it runs `npm install -g dreamcontext@latest`, replacing the dev link with the registry version (0.24.1). Correct path: per-project `dreamcontext update`.

- **RELEASES.json version-string format drift (2026-08-26)**: the ledger stores versions in TWO formats — 26 records v-prefixed (v0.15.0), 23 bare (0.24.1). An audit comparing against npm registry produced 27 false 'never published' phantoms purely from prefix mismatch. Not cosmetic — it breaks reconciliation. Normalize on write, or audit/heal with a migration.

- **Version 0.25.0 skipped — RELEASES record lies (2026-08-26)**: 0.25.0's RELEASES.json entry says `status=planning` with empty `date`, but the version will never ship — version surfaces bumped directly from 0.24.1 to 0.26.0 (local rollout only; npm registry still 0.24.1). `core releases set-status` accepts only planning|released (no superseded verb), and there's no delete/rename, so the record cannot be corrected through the CLI. Hand-editing RELEASES.json bypasses validation. Record honestly: 0.25.0 exists in the ledger but will never publish. Related debt: v0.24.1 on npm has no git tag (heal target: commit 4ed2819).

- **Account rate-limit % comes from Claude Code's OWN local cache (2026-08-23)**: the 5-hour/weekly caps have no token source — they are percentages the CLI caches in `~/.claude.json` under `cachedUsageUtilization`. Traps: the `five_hour`/`seven_day` summaries hold their number under `utilization`, only `limits[]` uses `percent`, and `limits[]` nests INSIDE `utilization`. That file also holds `oauthAccount`/`accountUuid`/spend, so the wire shape is built field-by-field, never spread. Source: file:src/lib/claude-usage.ts.

- **Sub-agents run on OPUS, never Fable (2026-08-23, owner directive)**: every dispatched sub-agent — Agent-tool judges/explorers AND CLI builder sessions (`claude -p --model …`) in goal-skill/curator/council flows — runs `--model opus`, never the orchestrator's own Fable model. Fable is the main-loop model only; it does not inherit downward. Pass the model explicitly on every dispatch — an omitted model silently inherits the parent.
