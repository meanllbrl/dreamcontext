## Orchestrator-skill + sub-agents family pattern (2026-06-21, extended 2026-06-25 with deep-research)

Interactive user-facing skills follow the pattern: (1) self-recognition/proactive offer when a condition is detected; (2) scout/audit sub-agent gathers context and proposes a plan; (3) user confirms the plan; (4) executor/ingestor sub-agents fan out in parallel per domain; (5) verifier sub-agent gates completion. Skills in this family (goal-skill, initializer, curator, deep-research) ship as CORE skills (always installed via installCoreForPlatform, manifest kind 'core'), not optional packs. When a new orchestrated skill needs a worker, REUSE an existing sub-agent rather than creating a new one — deep-research reuses dreamcontext-explore as its searcher and verifier explicitly because sub-agents cannot reliably fan out to further sub-agents in Claude Code. Single source of truth is enforced: parallel paths for the same role violate the no-duplication principle and must be collapsed.

**Context:** Core pattern for interactive orchestrator skills in the dreamcontext ecosystem. This pattern is well-documented across multiple skill implementations and is referenced in the skill development guidelines.

## Excalidraw boards: render via canvas editor (view mode), NOT exported SVG (2026-06-17)

The dashboard MUST render Excalidraw boards using the live `@excalidraw/excalidraw` canvas editor in view mode (ExcalidrawCanvas.tsx), not `exportToSvg()`. Reason: a large board's exported SVG is rasterized once by WebKit/WKWebView then sampled down on zoom — output is soft and blurry. The canvas editor re-draws per zoom so text and embedded screenshots stay crisp at any scale. fit-and-center is triggered after mount + layout-settle timer + ResizeObserver to ensure the flex-pane has reached its final size. Do NOT revert to SVG export for boards. ExcalidrawPreview MUST gate the loading spinner on `assetsQuery.isLoading` (not `assetFiles === undefined`): on an asset-fetch error the board MUST mount and render without images rather than spinning forever behind a permanent overlay.

**Source:** commit:d106c5c; commit:d30bac1; file:dashboard/src/components/core/ExcalidrawCanvas.tsx; file:dashboard/src/components/core/ExcalidrawPreview.tsx; changelog:2026-06-17|dashboard

**Context:** Implementation detail for dashboard Excalidraw rendering. The pattern is well-established in the codebase.

## Board embedded images resolved server-side via /api/knowledge-assets + sharp WebP (2026-06-17, hardened d30bac1)

Obsidian stores embedded screenshots in Excalidraw boards as `## Embedded Files` wikilinks (not base64 inline). The canvas renderer cannot resolve vault-relative paths client-side. GET /api/knowledge-assets/:slug parses the `## Embedded Files` map, resolves each path under the vault root (containment-guarded, images only), downscales + recompresses to WebP via sharp (optional — falls back to original), caches by path+mtime keyed to path+mtime. The renderer uses a single high-quality pass — the two-pass low/high progressive-load was removed (d30bac1) because the canvas freezes initialData at mount and a low→high swap was impossible. assetCache bounded to a 256-entry LRU to prevent unbounded growth in a long-lived server.

**Source:** commit:d106c5c; commit:d30bac1; file:src/server/routes/knowledge.ts; changelog:2026-06-17|dashboard

**Context:** Server-side image resolution for Excalidraw boards. Implementation detail well-documented in the route code.

## ClickUp post-sleep sync: ratePerMinute 90 + failedPushes + auto-retry in sleep done (2026-06-15)

The ClickUp adapter MUST be initialised with ratePerMinute: 90 (not 100) to maintain deliberate headroom under ClickUp's 100/min hard cap — full post-sleep bulk pushes were hitting 429 at the window edge with zero margin. maxRetries: 5 with Retry-After-respecting exponential backoff. SyncReport carries a structural failedPushes: string[] so partial pushes cannot masquerade as success. sleep done auto-retries the full sync once on non-empty failedPushes, then emits a red error() with the stale task list + remediation hint if any remain (prior behaviour: dim report.errors[0] was invisible).

## Federation is read-only live-reference — no copy-sync, ever (2026-06-15, ★★, supersedes copy-based v0.8.0 model)

dreamcontext federation MUST maintain single-source-of-truth. A 'reads' connection means recall queries live across the peer vault at call time — nothing is ever copied or materialised locally from a peer. The copy-based sync+drain+digest-inbox model (v0.8.0) was reverted after a user correction: "a reads connection COPIES peer content instead of reading it live — fix the read path so it references." sync and drain are now inert no-ops preserved for the roadmap but NOT active. 'federation purge' removes any stale materialised docs. The Excalidraw federation diagram still shows the old push/pull model — it needs regeneration. Do NOT reinstate copy-based federation without explicit instruction; it violates the single-source-of-truth constraint that is a hard requirement for this project.

## Person tags are the single source of truth for task assignment (2026-06-15)

The scalar 'assignee' field in task frontmatter is legacy and migrates to person tags ('person:<slug>') on read; it is then deleted. Effective assignees = union(person tags, legacy scalar field) filtered to roster. The UI must surface a person picker (not a text field) so users can assign without knowing internal slugs. ClickUp sync sends CREATE with assignees:ids and UPDATE with an {add, rem} delta. The routes/tasks.ts roster merge is slug-based and provider-agnostic (no 'clickup' substring). When removing an assignee via any UI path (chip row or tag row), both the person tag AND the legacy assignee field must be cleared atomically to prevent ghost reappearance.

## ClickUp singleton tag reconciliation: use live PUT-response tags, not base snapshot (2026-06-15)

Tags that must be single-valued (e.g. version:<v>) MUST reconcile against the live remote tags returned in the PUT response, not the base snapshot. The base snapshot drifts whenever the value is changed via a bound custom FIELD rather than the tag itself (clickup.ts:1078 — field outranks tag). Non-singleton tags continue to diff against the base snapshot (so remote-only tags survive until a pull merge). Pattern: strip all live version:* tags except the desired one; add the desired tag if absent from the live set. Do NOT revert to base-snapshot-only diffing for version tags — it reliably produces duplicate version:x + version:y on the remote.

## Sleep/goal agent task-status policy: reality-based, not reflexive (2026-06-15, canonical)

Removed the hard rule that sleep/goal agents always bump touched tasks to in_review. New policy everywhere (agents/sleep-tasks.md, skill/SKILL.md, skill-packs/goal-skill/SKILL.md): use `completed` for done+low-risk+already-validated work (chores, docs, mechanical refactors, tests-green fixes); use `in_review` ONLY when a human genuinely must verify something (user-facing behaviour change, design/architecture decision, risky/critical-path work, or to hand over a close decision on superseded/abandoned tasks). Goal-skill Phase 6 PASS now closes directly — validation passing with evidence IS the definition of done. Test: "would the user actually want to look at this before it's closed?" If yes → in_review; if it's done and nothing to second-guess → completed. When genuinely unsure, prefer in_review.
