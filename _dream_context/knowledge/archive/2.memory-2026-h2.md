## Orchestrator-skill + sub-agents family pattern (2026-06-21, extended 2026-06-25 with deep-research)

Interactive user-facing skills follow the pattern: (1) self-recognition/proactive offer when a condition is detected; (2) scout/audit sub-agent gathers context and proposes a plan; (3) user confirms the plan; (4) executor/ingestor sub-agents fan out in parallel per domain; (5) verifier sub-agent gates completion. Skills in this family (goal-skill, initializer, curator, deep-research) ship as CORE skills (always installed via installCoreForPlatform, manifest kind 'core'), not optional packs. When a new orchestrated skill needs a worker, REUSE an existing sub-agent rather than creating a new one — deep-research reuses dreamcontext-explore as its searcher and verifier explicitly because sub-agents cannot reliably fan out to further sub-agents in Claude Code. Single source of truth is enforced: parallel paths for the same role violate the no-duplication principle and must be collapsed.

## Excalidraw boards: render via canvas editor (view mode), NOT exported SVG (2026-06-17)

The dashboard MUST render Excalidraw boards using the live `@excalidraw/excalidraw` canvas editor in view mode (ExcalidrawCanvas.tsx), not `exportToSvg()`. Reason: a large board's exported SVG is rasterized once by WebKit/WKWebView then sampled down on zoom — output is soft and blurry. The canvas editor re-draws per zoom so text and embedded screenshots stay crisp at any scale. fit-and-center is triggered after mount + layout-settle timer + ResizeObserver to ensure the flex-pane has reached its final size. Do NOT revert to SVG export for boards. ExcalidrawPreview MUST gate the loading spinner on `assetsQuery.isLoading` (not `assetFiles === undefined`): on an asset-fetch error the board MUST mount and render without images rather than spinning forever behind a permanent overlay.

## Multi-global-CLI staleness + npm/desktop version independence (2026-06-14)

The thin-shell Tauri app resolves the global CLI via `$SHELL -lc command -v dreamcontext`. On a machine with BOTH homebrew and nvm node, homebrew resolves first. ensureCliInstalled() may install to homebrew, so the app runs a DIFFERENT (older) global than the one a dev updated via nvm. Real fix: publish to npm so all resolved globals converge to the same version. npm CLI version line and desktop app version line are INDEPENDENT: npm 0.8.x and desktop v0.8.x tags happen to share the same number but are NOT coupled. The desktop release tag is v0.8.1; the npm package was published as 0.8.0 then will be 0.8.1. Same numbers are coincidental. Never assume a version bump to one implies the other.

## Scaffold child-spawn + global CLI auto-provision (2026-06-13)

POST /api/launcher/scaffold runs init + setup via execFile (no shell, explicit arg array, 120 s timeout) with cwd=target directory. The long-lived shared server's process.cwd() is never mutated. No new Rust/Tauri command needed — the existing folder-picker dialog + WebviewWindow API already handle directory selection and window management. ensureCliInstalled() probes command -v dreamcontext via $SHELL -lc so a Finder-launched Tauri app sees nvm/brew PATH entries absent from a default non-login env. When missing, runs npm install -g dreamcontext@latest. Rationale: scaffolded projects' .claude/ hooks call npx dreamcontext hook … — without a global CLI, npx hangs or fails silently in a non-interactive hook context.

## Multi-vault multi-window + Tauri v2 ACL (2026-06-13)

The Tauri desktop beta uses a single shared Node server in "launcher mode" (contextRoot=null). Each vault opens in its own native window via WebviewWindow; no in-window switcher. Vault binding is per-request: the URL ?vault=<name> parameter is promoted to an X-Dreamcontext-Vault header by server middleware, then a strict name-only contextRoot resolver runs on each request. This prevents React-Query cache thrash between vaults and avoids a confused-deputy path-fallback risk. Supersedes the v0.6 "one server per vault" model. Tauri v2 treats http://127.0.0.1:PORT as a REMOTE origin. Custom Rust commands invoked from remote-loaded pages are rejected by the ACL with "Command X not allowed by ACL" regardless of capability config. Fix: use the built-in invoke_handler `WebviewWindow` API (capability: `core:webview:allow-create-webview-window`) — built-in commands bypass the remote-URL ACL check. Do NOT add custom Tauri commands for any functionality callable from the dashboard; route through the existing /api/* Node server instead.

**Source:** knowledge:desktop-beta-tauri-multivault; file:src/server/middleware.ts; file:desktop/src-tauri/capabilities/default.json

## Board embedded images resolved server-side via /api/knowledge-assets + sharp WebP (2026-06-17, hardened d30bac1)

Obsidian stores embedded screenshots in Excalidraw boards as `## Embedded Files` wikilinks (not base64 inline). The canvas renderer cannot resolve vault-relative paths client-side. GET /api/knowledge-assets/:slug parses the `## Embedded Files` map, resolves each path under the vault root (containment-guarded, images only), downscales + recompresses to WebP via sharp (optional — falls back to original), caches by path+mtime keyed to path+mtime. The renderer uses a single high-quality pass — the two-pass low/high progressive-load was removed (d30bac1) because the canvas freezes initialData at mount and a low→high swap was impossible. assetCache bounded to a 256-entry LRU to prevent unbounded growth in a long-lived server.

## ClickUp post-sleep sync: ratePerMinute 90 + failedPushes + auto-retry in sleep done (2026-06-15)

The ClickUp adapter MUST be initialised with ratePerMinute: 90 (not 100) to maintain deliberate headroom under ClickUp's 100/min hard cap — full post-sleep bulk pushes were hitting 429 at the window edge with zero margin. maxRetries: 5 with Retry-After-respecting exponential backoff. ## ClickUp singleton tag reconciliation: use live PUT-response tags, not base snapshot (2026-06-15)

Tags that must be single-valued (e.g. version:<v>) MUST reconcile against the live remote tags returned in the PUT response, not the base snapshot. The base snapshot drifts whenever the value is changed via a bound custom FIELD rather than the tag itself (clickup.ts:1078 — field outranks tag). Non-singleton tags continue to diff against the base snapshot (so remote-only tags survive until a pull merge). Pattern: strip all live version:* tags except the desired one; add the desired tag if absent from the live set. Do NOT revert to base-snapshot-only diffing for version tags — it reliably produces duplicate version:x + version:y on the remote.

## Extracted 2026-07-27 (ceiling-blocked promotion — four reusable desktop-agent decisions)

- **CSS Motion Path for SVG flow animations (2026-06-06)**: Animate `offset-distance` on a small dot element along an `offset-path` SVG path, NOT `stroke-dashoffset` on the full path. `stroke-dashoffset` re-rasterizes the entire stroke on the main thread every frame (visible stutter at >10 dots). Motion Path is compositor-class — only a tiny region is dirty per frame; measured worst-frame 9-11ms, 0 jank at ~27 dots. Glow = radial-gradient fill on the dot (rasterized once), not a per-frame drop-shadow filter. Source: dashboard/src/components/about/FlowDiagram.css.
- **`overflow-x: clip` vs `overflow-x: hidden` for sticky descendants (2026-06-06)**: `overflow-x: hidden` establishes a scroll container on that axis (the other axis computes to `auto`), which causes `position: sticky` descendants to resolve to that element as their scroller rather than the real page scroller — breaking the sticky behavior entirely. Use `overflow-x: clip` to clip horizontally without establishing a scroll container. Source: dashboard/src/components/about/AboutPage.css; blocking issue discovered during sticky scrub section implementation.
- **bundleDir skill-pack install mechanism (2026-06-05)**: CatalogStandalone entries with `bundleDir:true` copy the full directory via cpSync rather than a single SKILL.md, preserving binaries and exec bits. CJS subtrees under the ESM host must include a `package.json {"type":"commonjs"}` to prevent module resolution failures. This is the canonical pattern for code-bearing skills (excalidraw, video-watching). Source: src/lib/install-packs.ts; skill-packs/catalog.json.
