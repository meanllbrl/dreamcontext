### 3. `dashboard/src/lib/scopedStorage.ts` (new)
```ts
export const SCOPE_PREFIX = 'dreamcontext:';
export function scopedKey(vault: string | null, key: string): string;
export function readScopedRaw(vault: string | null, key: string): string | null;
export function writeScopedRaw(vault: string | null, key: string, value: string): void;
export function readScoped<T>(vault: string | null, key: string, fallback: T): T;
export function writeScoped<T>(vault: string | null, key: string, value: T): void;
export function removeScoped(vault: string | null, key: string): void;
```
Pinned semantics — a reviewer will check each of these:
- `scopedKey(null, k) === k` — the LEGACY key VERBATIM, **not** `dreamcontext:k`. A null vault
  means launcher/browser and must behave byte-identically to today.
- `scopedKey(v, k) === `${SCOPE_PREFIX}${v}:${k}`` for a non-null vault.
- Migration lives in the **raw** layer so one code path serves both the JSON keys and the
  `'1'`/`'0'` string keys: on first read for a (vault, key) pair with a non-null vault, if the
  scoped key is absent and the LEGACY key is present, copy legacy → scoped and then
  `localStorage.removeItem(legacy)`.
- Guard migration with a module-level `Set<string>` of already-migrated `vault + '|' + key`
  pairs so it runs at most once per pair per page. Idempotent.
- Deliberate, documented consequence (put it in a comment): the legacy value goes to whichever
  project reads it FIRST, and the legacy key is then deleted, so a second vault reading the
  same legacy key gets the fallback. Copy-without-delete would re-seed every future project
  from a value that belonged to whatever project happened to be open last. This mirrors
  `hooks/usePersistedState.ts:25-34`.
- Every localStorage access wrapped in try/catch (private mode / quota) — never throw into a
  render. Corrupt JSON falls back to `fallback`.
