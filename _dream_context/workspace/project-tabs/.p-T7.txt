export interface OpenProject {

It owns and renders:

  that case; reuse whatever `Header.tsx` does today, do not invent a new probe),

  `SleepDebtTracker`, the manual refresh button and `UpdateBadge` are per-vault and STAY in the

State rules:
- **NO PERSISTENCE.** On mount, `open` is exactly one entry: `initialVault`. Never read or write
  a tab list to localStorage or the server. Quitting and relaunching must come back with one project.
- `instanceId` is a stable per-tab string (`inst-1`, `inst-2`, …) from a counter. It must NOT be
  reused after a close.
- `addTab` order of checks — implement all four now, even though the window-registry parts land
  in Wave 4 (leave a clearly-marked TODO calling out T20 for step 2):
  1. already a chip here → `activate(vault)`, return `'focused-tab'`
  2. (T20, Wave 4) open in ANOTHER window → focus it, return `'focused-window'`
  3. at `MAX_LIVE_INSTANCES` → evict the OLDEST instance that is `rollup !== null && rollup.live === 0`

- **THE CEILING'S NULL CASE IS LOAD-BEARING.** `rollup === null` means "has not published yet",

## 2. `ProjectTabs.tsx` + `.css` — the chip strip
```tsx
export interface ProjectChip {
  vault: string; active: boolean; cold: boolean;
  worst: SessionStatusKind; live: number; waiting: number; bounceNonce: number;
}
export function ProjectTabs(p: {
  chips: ProjectChip[];
  onActivate(v: string): void;
  onClose(v: string): void;
  onAdd(): void;
  onDetach(v: string): void;
}): JSX.Element;
```
Chip anatomy, in order: **status dot · project name · badge · ×**. A `+` sits at the end of the
strip. The active chip is filled and outlined; the others are plain outline.

In THIS wave `worst`/`live`/`waiting`/`bounceNonce` arrive as inert defaults (T19 feeds them in
Wave 4) — render the dot and OMIT the badge entirely when `live === 0`. Build the visual states
now so Wave 4 only has to supply data.

**Rule 1 — freeze while the pointer is in the strip.** Centre-aligned means every add/close
shifts every chip sideways, so a close puts the neighbouring chip under the cursor and invites
a second accidental close. On `pointerenter`, snapshot the strip's current geometry and hold it
(a leading spacer + fixed chip widths); a closed chip's slot stays EMPTY. Release and re-centre
on `pointerleave`. This is the behaviour Chrome uses for tab widths, for the same reason.

**Rule 2 — fall left when it no longer fits.** A `ResizeObserver` on the strip: while it fits
between the traffic-light inset and the right cluster it stays centred; the moment it would
touch the right cluster, switch to `justify-content: flex-start` + `overflow-x: auto`. A clipped
centred strip reads as broken alignment.

- Tauri drag: put `data-tauri-drag-region` on the strip's EMPTY area only, never on a chip or
  the `+` (a drag region swallows clicks).
- `+` calls `onAdd()`, which opens the ProjectSwitcher (T9 wires that; just call the prop).
- Right-click a chip → "Open in New Window" → `onDetach(vault)`. There is deliberately **no**
  drag-a-chip-out gesture; it was cut.
- `prefers-reduced-motion`: no bounce/pulse, colour changes only.
- Use existing design tokens for every colour, radius and spacing. Zero hardcoded hex.
