front-most one. `pushOverlay` DE-DUPES BY ID (`:14-16`). With N project instances in one realm,
two instances that push the SAME literal id are the same entry — so instance A closing its
palette pops instance B's, and Esc breaks in B.

## THE FIX — deliberately minimal
Do NOT change `pushOverlay`/`popOverlay`/`isTopOverlay`'s signatures. Changing them would force
edits to the three `useId()` sites for no benefit. Instead:

```ts
// lib/overlayStack.ts — ADD ONE FUNCTION, everything else untouched
export function popAllWithPrefix(prefix: string): void;

// lib/useOverlayId.ts — NEW (keeps overlayStack framework-free)
export function useOverlayId(local: string): string;   // `${instanceId}::${local}` from useVault()
```
`useOverlayId` is a hook (it reads `useVault()`), which is why it lives in its own file rather
than inside the framework-free `overlayStack.ts`. Outside a `VaultProvider` `instanceId` is
`''`, giving `'::command-palette'` — still unique, because a launcher window has exactly one of
each.

Then at each of the five sites: `const overlayId = useOverlayId('command-palette')` (etc.) at
the top of the COMPONENT body, and pass that where the literal was. In `AnnouncementsModal.tsx`
the literal is a module constant (`:9`) — move it inside the component.

`popAllWithPrefix(prefix)` exists so a chip going background can drop its own overlays in one
call. Nothing calls it yet — that is fine and intended; ship it with a doc comment saying who
will (`WindowChrome`, when a chip is deactivated).
