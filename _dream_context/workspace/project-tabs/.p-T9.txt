`ProjectSwitcher` is the ⌘P palette. Today it assumes one window per project: picking a project

TWICE (launcher + vault branch of `App.tsx`); T7 now mounts it ONCE inside `WindowChrome`.

   identifies anything — a window now holds N projects. Use `useChrome().activeVault`.

   switcher is rendered in the launcher window (no provider). If `useChrome()` cannot be called

   window**: `await chrome.addTab(v.name)`. Handle all four return values:

   - `'refused-ceiling'` → do NOT close silently. Show the reason in the palette: every open
     project has a live session, so a new tab would have to evict one. The user must learn why
     nothing happened.
   **⇧-click (and ⇧+Enter) keeps the OLD behaviour** — `openVaultWindow(v.name)`, a real second
   OS window. That is the escape hatch and it must keep working.
   In the launcher window (no chrome) the default stays `goToProject` exactly as today.

3. **⌘1-9 (~:132-137) now walks THIS WINDOW'S CHIPS, not the vault registry.** Today it indexes
   `openable` — every registered vault. That is the wrong list: chip order is not registry
   order. Index `chrome.open` instead and call `chrome.activate(...)`. In the launcher window
   keep today's `goToProject` behaviour.

4. `goHome()` is unchanged. The Launcher row stays.
