## THE PROBLEM (verified against the real code by an independent reviewer)
Three things drive `ensureOpen()`/`fitVisible()` in `AgentSurface.tsx` today:
- `useLayoutEffect` keyed `[panes, expanded]` (~:1335-1368) — appends the container to its slot
  then `s.ensureOpen()`, then a rAF that does `ensureOpen()+fitAndResize()` for the foreground
- `useEffect` keyed `[expanded, fitVisible]` (~:1413-1417) — a rAF `fitVisible()`
- a 150ms-debounced `ResizeObserver` on the host + slots (~:1430-1447), gated `if (!expanded) return`

**None of them fires when the INSTANCE becomes visible.** `isActive` is in no dependency array.
And in `agentSession.ts`, `ensureOpen()` (~:678-712) bails while
`container.offsetParent === null` — permanently true under `display:none` — so a terminal
opened while its project was a background chip never opens, and `fitAndResize()` (~:362-368)
returns early while `!session.opened`, so the PTY keeps the server's default grid and the TUI
renders at the wrong width.

## 1. `agentSession.ts` — make the focus grab opt-out
```ts
ensureOpen: (opts?: { focus?: boolean }) => void;    // was () => void
```
- `function ensureOpen(opts: { focus?: boolean } = {})`, and inside `doOpen()` change the
  unconditional `term.focus()` (~:700) to `if (opts.focus !== false) term.focus();`.
- Default stays `true`, so every existing call site behaves exactly as today.
- WHY: once a background instance can open a terminal, an unconditional `term.focus()` would
  yank the caret out of whatever the user is typing in the FOREGROUND project.
- Change nothing else in this file. In particular do not touch the WS URL, `fitAndResize`'s
  early return, the flow-control acks, the settle/idle classifier, or `dispose()`.

## 2. `AgentSurface.tsx` — re-drive on activation
- `const { isActive } = useVault();`
- Add ONE new effect, next to the existing `expanded` one:
  ```ts
  useEffect(() => {
    if (!isActive) return;
    const raf = requestAnimationFrame(() => fitVisible());
    return () => cancelAnimationFrame(raf);
  }, [isActive, fitVisible]);
  ```
  The rAF matters: a freshly-shown container only has a non-null `offsetParent` after the
  browser has laid it out.
- Pass the focus flag at the two existing drive points (~:1355 and ~:1365):
  `s.ensureOpen({ focus: isActive })`.
- Tighten the ResizeObserver gate (~:1431) to `if (!expanded || !isActive) return;` so a hidden
  instance stops observing and cannot churn.

## 3. `AgentSurface.tsx` — dispose on unmount (finding M2)
Today NOTHING disposes sessions when this component unmounts: `dispose()` is reached only from
`closeSessionById` (~:492), `resumeChatInTerminal` (~:581), `resumeChatSession` (~:598) and
`openAgentInChat` (~:658). That is correct today because the surface outlives everything.

It stops being correct the moment a `ProjectInstance` can be torn down — the ceiling rule
evicts an idle instance into a "cold chip", and closing a chip unmounts one. Without a teardown
that leaks the PTY, the WebSocket, the xterm, the `MutationObserver` and the per-session
`AGENT_SETTINGS_EVENT` listener, and leaves an orphaned `claude` process on the machine.

Add an unmount-only cleanup:
```ts
useEffect(() => () => {
  sessions.current.forEach((s) => { try { s.dispose(); } catch { /* best-effort */ } });
  sessions.current.clear();
}, []);
```
Empty dep array — it must run ONLY on unmount, never on a re-render. `dispose()` is already
individually try/caught internally, but wrap per-session anyway so one throw cannot abort the
rest.
