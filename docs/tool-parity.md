# What runs on which tool

Generated by `scripts/gen-tool-parity.mjs` from `docs/tool-parity.json` and `src/lib/t3-bridge/headless-envelope.ts`. Do not edit by hand.

**works** = covered by tests and a real run. **experimental** = built and tested against a fake, not yet proven on a real account. **Claude only** = stays on Claude on purpose.

| Antigravity chat | - | - | Experimental, proved with real turns on one account (agent 1.4.1): sign-in, memory, approval cards, resume, skills listed and read from the account's profile, the brain MCP server, its identity. The write gate is the agent's own PreToolUse hook in each account's profile: real turns refused shell and file-tool writes to marketing tokens, in every mode and inside the agent's own sub-agents, and a project's .agents/hooks.json cannot switch it off. A Super child runs with `super delegate --tool antigravity`: no card, no child without the gate, `super read` returns its words. It has no OS sandbox, so a child or a Bypass agent can write outside the project. Stop reads the agent's conversation file, so sleep sees the turns. Our sub-agent roles (ours, the skill packs' and the owner's `~/.claude/agents`) are a plugin in each account's profile, called with `invoke_subagent`, refreshed as a chat opens and by the project catch-up; a project's own `.claude/agents` role is made with `define_subagent` from its file. Files and tests only, no real turn: the account is out of quota until about 8 Nov. The owner's tool servers reach its chats, and Settings > Tool servers shows what a live session reports: a server is asked first and left out if it does not answer, because one bad server refuses every turn of a session, and a server that wants a sign-in stays out because the agent has none. `sleep auto-run --tool antigravity` and Sleep now run on it (fake agent only, no real turn); automations, AI Team and Terminal stay off. Eco and account moves are proved against a fake agent only, and compaction was never reached on a real turn: the server refused past about 1M tokens. Context rides in the user's message, because ACP has no untrusted channel. OpenCode was dropped by the owner. |
