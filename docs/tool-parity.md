# What runs on which tool

Generated by `scripts/gen-tool-parity.mjs` from `docs/tool-parity.json` and `src/lib/t3-bridge/headless-envelope.ts`. Do not edit by hand.

**works** = covered by tests and a real run. **experimental** = built and tested against a fake, not yet proven on a real account. **Claude only** = stays on Claude on purpose.

## Features

| Feature | Claude | Codex | Note |
|---|---|---|---|
| Chat | works | works | Checked live on the owner's account in W1. |
| Model picker, Sign in, favourites | works | works |  |
| Switching tool inside a chat | works | experimental | Opens a new chat beside the old one after one confirm. The text goes to the other vendor. |
| Several accounts, limit switch | works | works | Automatic moves between tools stay off. |
| Brain, recall, task log | works | experimental | Runs the same hooks. In a chat the `.env` gate works only after `dreamcontext install --tool codex` and trusting the folder and its hooks. The live check is the owner's. |
| Eco mode | works | experimental | Proved against a replayed Codex. |
| Automations | works | experimental | No home board, no task steps. Sandboxed with no network, so a job that needs the web stays on Claude. Runs only after `dreamcontext install --tool codex` and trusting the folder and its hooks in Codex, which is what keeps `.env` closed. |
| AI Team agents | works | experimental | Same limits as automations. Changing the tool asks for approval again. |
| Super Agent | works | Claude only | The lead stays on Claude: its verbs are off the brain MCP on purpose. |
| Super Agent's delegated child | works | experimental | `super delegate --tool codex`. stdio MCP servers only, and the same `.env` gate as automations. |
| Terminal | works | experimental | `codex` on the chat's account, always workspace-write. |
| Sleep | works | experimental | `sleep auto-run --tool codex`. One turn with no sub-agents. No live run recorded yet. |
| Antigravity, OpenCode | - | - | Wave 5. |
