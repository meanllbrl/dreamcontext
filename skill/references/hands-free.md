# Hands-free mode — the phone drives this laptop through a tunnel

Load this reference when the owner wants to work from the phone, "go hands-free", "eller serbest", manage sessions from a walk, or come back ("return", "dön"). It also covers a leaked passphrase, a refused start and the fixed address.

Every subcommand and flag below is read from `src/cli/commands/handsfree-mac.ts` (`registerHandsfreeMacCommand`, mounted under `dreamcontext handsfree`). The logic is in `src/lib/handsfree/mac/session.ts`, and the desktop app calls it through `src/server/routes/handsfree-mac.ts`.

**Not to be confused with** the **tailnet phone path** (`src/server/remote-access.ts`), a token-bearing device on the owner's tailnet reaching the dashboard server directly.

**There is one mode.** The earlier cloud-trip mode was removed on 2026-10-16; every hands-free run is Mac mode.


The work never leaves the laptop. While Mac mode is on, the desktop app's own server runs a second listener (the **phone listener**, 127.0.0.1 only) and a pinned `cloudflared` tunnels a public `https://` address to it. The phone opens that address, signs in (scan the one-time QR, or type the 6-word passphrase) and drives the SAME chats the desktop window runs: no copy, no lock, no merge. The Mac stays awake with the lid closed (`pmset disablesleep 1`) in Low Power Mode; **Return** restores both. Use it when the owner wants to "manage sessions from the phone on a walk" without a VPN on the phone.

|---|---|---|

| `dreamcontext handsfree mac start [--project <name>]… [--bag \| --no-bag]` | Phone listener → cloudflared (sha256-pinned in `assets/cloudflared-pins.json`) → reachability probe → keep-awake + LPM, for the chosen projects (`--project` repeatable; default the project the CLI runs in; an unknown name lists the registered ones). `--bag` / `--no-bag` picks Bag mode (see Heat); omitted = the last choice. | `dreamcontext handsfree mac stop` | **Return**: phone sockets close 4401 and their chats detach (still running; the desktop reattaches), every Mac device is signed out, the tunnel and listener stop, sleep and LPM are restored. | `stop()` |
| `dreamcontext handsfree mac status` | Phase, address, the projects on the phone, the bag mode (the run's, or the next start's while off), battery, signed-in phone count, `thermal: <state>[, N slowed]`. | `status()` |
| `dreamcontext handsfree mac password` | New passphrase (TTY only); signs every phone out. | `setPassword()` |
| `dreamcontext handsfree mac devices [revoke-all]` | Lists signed-in phones; `revoke-all` signs them out now and CUTS a turn a phone is running (a desktop-held chat is never touched). | `revokeAll()` |

The CLI calls the running desktop app (`~/.dreamcontext/handsfree-mac/server.json`); with the app closed it says so. In the app: the sheet's Mac panel (setup, Start, "QR'ı göster", battery, devices + "Hepsini çıkar", Dönüş), the chrome chip **Telefonda**, and Settings → Hands-free → fixed address.

**Projects.** Start names the projects the phone may open (the app's checklist, current project pre-checked; the CLI's `--project`). The phone lists and reaches only those: `/api/vaults` and the live chats are filtered, a request or chat socket naming another project is 403 `phone_unavailable`, a request naming none runs on the one chosen project (400 `phone_vault_required` when several are chosen), and a conversation id from another project is refused on every route that takes one (`transcriptOwnerCheck` in `src/lib/transcript-locate.ts`: the transcript's launch dir decides, a worktree counts as its project's). Changing the set = Return + start. This scopes what the APP shows; it is not a sandbox: a bypass chat in a chosen project can still read any folder on the Mac.

**Trust model (what to tell the owner).** A phone socket is NEVER loopback, although cloudflared dials it from 127.0.0.1 (`src/server/phone-origin.ts`). A signed-in phone reaches the whole dashboard API except a laptop-only deny list; the audit table is `ROUTE_POLICY` in `src/lib/handsfree/mac/route-policy.ts` (every registered route: allow or deny, why, what body it may send, which project it acts on), and a route with no row is refused, so a new route never reaches the phone silently. Denied: Settings, the launcher, Mac-mode administration, windows, the Assistant, installers, secrets, sign-ins, voice, Finder/Terminal. Only the chat WebSocket upgrades, only the tunnel's own Origin, never a cross-site request (`Sec-Fetch-Site`), always `nosniff`, only a Mac device session (`~/.dreamcontext/handsfree-mac`). The main listener refuses any request or upgrade carrying a Cloudflare header, so a tunnel pointed at the wrong port reaches nothing. Residual risks: a leaked passphrase or QR is control of the whole Mac while on (bypass-mode chats included); Cloudflare terminates TLS; a quick-tunnel restart changes the address.

**A garbled voice message is never sent.** The Mac scores every phone take (decoding confidence, language vs the conversation's recent clear takes, alphabet, loops); a suspect one is transcribed once more in the context language, and if both attempts are garbled nothing is sent: the composer shows "Anlayamadım, tekrar eder misin?" and the phone says it (silent switch off). A dictated message carries `<voice-take ref>`, so the agent can `dreamcontext voice retry` it (cli-reference.md). Takes are kept 24 h / 200 MB in `~/.dreamcontext/logs/voice-takes/` (0700).

**Installed app and notifications.** On the fixed address the phone can add the page to its Home Screen (manifest + icons; iOS keeps the installed app's sign-in apart from Safari's, so it asks for the passphrase once). The chat drawer offers "Turn on notifications" inside the installed app. The Mac then pushes (Web Push, VAPID keys and subscriptions 0600 in `~/.dreamcontext/handsfree-mac`) on exactly three events of a chosen project's chat: a question, a permission request (tool name only), a finished turn (not one the owner interrupted). A tap opens that chat. No push for the chat that phone shows on screen, none after logout, revoke or Return. A quick address cannot carry notifications (it changes every start).

**One chat, two screens.** Only one screen drives a chat. An explicit tap (drawer "Mac'te açık", "Buraya al") takes it and the other screen gets close code 4409 and shows "Buraya al"; automatic reconnects and reload restores are passive (`reattach=passive`) and never take a chat from a live screen. A phone whose network dropped silently is detected by a ping probe (`HOLDER_PROBE_MS`).

**Refusals.** `mac_not_setup`, `mac_sudo_missing` (run setup again), `mac_tunnel_failed` / `mac_probe_failed` (nothing was left running), `mac_admin_cancelled`. At ≤15% battery and discharging the Mac is allowed to sleep again (no re-arm). A crash leaves nothing open: the next app start kills the orphan cloudflared (only if it is ours), signs phones out and restores power; a watchdog also ends cloudflared within seconds of the server dying. A tunnel that stops for good while on (its restart budget spent) ends Mac mode the way Return does, since the phone can no longer reach the Mac to press it; the notification says so. Power that an end could not restore (sudo refused) waits in `~/.dreamcontext/handsfree-mac/power-pending.json` and is restored at the next start and app start, and every notice names a step that failed instead of claiming it.

**Phone logs.** The Sohbetler list's "Bağlantı kaydını Mac'e gönder" lands the phone's own connection log (the last 10 minutes of socket drops, reattaches and card mounts; no message text) in `~/.dreamcontext/handsfree-mac/phone-logs/` (newest 20). When the owner says the phone misbehaved, read the newest file there before guessing.

**Heat (the thermal governor).** Slowing happens only in **Bag mode (Çanta modu)**: a switch under the project checklist (the CLI's `--bag` / `--no-bag`), chosen at start and remembered in `~/.dreamcontext/handsfree-mac/prefs.json` (never chosen = on). Normal mode keeps keep-awake and Low Power Mode, still reads the heat for status, and slows nothing. Changing it = Return + start. A lid-closed Mac under full load heats with nothing to stop it, so while Mac mode is on in Bag mode the governor reads macOS `thermalState` every 20 s (no sudo). Nothing is ever killed or quit. At `fair` it moves the owner's own processes burning ≥ 50% CPU (≥ 15% at `serious`/`critical`, older than 20 s) to the efficiency cores with `taskpolicy -b`; children born under them are tracked too. After 6 nominal readings in a row (2 min), or 6 unreadable ones, everything goes back with `taskpolicy -B`, parents before children. Never slowed: claude chats, the dashboard server and the app above it, our cloudflared, and WebKit's XPC services. The phone chip says **Mac serinletiliyor** and the Mac panel **Mac ısındı · N iş yavaşlatıldı**; every clamp and release is logged to `~/.dreamcontext/handsfree-mac/thermal.log`. Return restores sleep and Low Power Mode first, then releases; whatever a quit could not release in time (800 ms) waits in `thermal-pending.json` and is released at the next app start. Accepted risks: a slowed test run can exceed Claude's Bash tool timeout while hot; browsers and emulators feel slow while hot; Safari tabs are spared with the WebKit exemption; `ps` %CPU is a decaying average; an MCP server under a claude can be slowed if it burns ≥ 15%; a child re-parented to launchd before the next tick escapes tracking; after a crash, or a quit past its release deadline, processes stay slowed until the app next opens (sleep and LPM are restored first regardless).

**Very hot: one heavy step machine-wide.** While macOS reports `thermalState` serious or critical (every mode, hands-free on or off; Bag mode alone does not lower it), `builder heavy` and `builder test` of every repo together run ONE heavy step at a time instead of 2 (the limit is read again every 20 s while waiting; a running step is never stopped; a busy exit 75 names the heat and the slot holder, and the hot default wait is 120 s). `super state`'s `machine.heat` (`thermal`, `heavyLimit`, `bag`) reports it; children are not limited. Browser verify scripts always go through `dreamcontext builder heavy --max-wait 1200 -- node scripts/verify/<x>.mjs`, in the background, never beside tests. During a hands-free run the first serious/critical reading sends one phone push (once a phone is subscribed), the Mac panel shows **Mac got very hot · heavy steps run one at a time**, and the phone chip says very hot. With Bag mode on, a calm note sits under the Bag switch on the Mac and once per run on the phone (dismissable); the phone chip reads **Mac · in the bag**.
