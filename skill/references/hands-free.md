# Hands-free mode — the phone drives this laptop through a tunnel

Load this reference when the owner wants to work from the phone, "go hands-free", "eller serbest", manage sessions from a walk, or come back ("return", "dön"). It also covers a leaked passphrase, a refused start and the fixed address.

Every subcommand and flag below is read from `src/cli/commands/handsfree-mac.ts` (`registerHandsfreeMacCommand`, mounted under `dreamcontext handsfree`). The logic is in `src/lib/handsfree/mac/session.ts`, and the desktop app calls it through `src/server/routes/handsfree-mac.ts`.

**Not to be confused with** the **tailnet phone path** (`src/server/remote-access.ts`), a token-bearing device on the owner's tailnet reaching the dashboard server directly.

**There is one mode.** The earlier cloud-trip mode was removed on 2026-10-16; every hands-free run is Mac mode.


The work never leaves the laptop. While Mac mode is on, the desktop app's own server runs a second listener (the **phone listener**, 127.0.0.1 only) and a pinned `cloudflared` tunnels a public `https://` address to it. The phone opens that address, signs in (scan the one-time QR, or type the 6-word passphrase) and drives the SAME chats the desktop window runs: no copy, no lock, no merge. The Mac stays awake with the lid closed (`pmset disablesleep 1`) in Low Power Mode; **Return** restores both. Use it when the owner wants to "manage sessions from the phone on a walk" without a VPN on the phone.

| Command | What it does | Source |
|---|---|---|
| `dreamcontext handsfree mac setup [--new-passphrase]` | Installs the sleep permission with ONE admin prompt (a sudoers drop-in granting exactly six `pmset` argv lines) and creates the phone passphrase, printed once and only on a TTY. | `session.ts` `setup()`, `power.ts` |
| `dreamcontext handsfree mac start [--project <name>]…` | Phone listener → cloudflared (sha256-pinned in `assets/cloudflared-pins.json`) → reachability probe → keep-awake + LPM, for the chosen projects (`--project` repeatable; default the project the CLI runs in; an unknown name lists the registered ones). Prints the address and a one-time sign-in link (TTY only). | `start({ vaults })` |
| `dreamcontext handsfree mac stop` | **Return**: phone sockets close 4401 and their chats detach (still running; the desktop reattaches), every Mac device is signed out, the tunnel and listener stop, sleep and LPM are restored. | `stop()` |
| `dreamcontext handsfree mac status` | Phase, address, the projects on the phone, battery, signed-in phone count, `thermal: <state>[, N slowed]`. | `status()` |
| `dreamcontext handsfree mac password` | New passphrase (TTY only); signs every phone out. | `setPassword()` |
| `dreamcontext handsfree mac devices [revoke-all]` | Lists signed-in phones; `revoke-all` signs them out now and CUTS a turn a phone is running (a desktop-held chat is never touched). | `revokeAll()` |
| `dreamcontext handsfree mac tunnel fixed <hostname> [--overwrite-dns]` / `tunnel quick` | A fixed address on the owner's Cloudflare domain (a locally-managed named tunnel; `login` runs with a private HOME so nothing lands in `~/.cloudflared`, and the zone cert is deleted after setup), or back to a new quick address per start. A hostname that already has a DNS record is refused (`mac_hostname_in_use`) before the login; `--overwrite-dns` replaces it only when the owner says so. | `tunnel.ts` `setupFixedTunnel()` |
| `dreamcontext handsfree mac uninstall` | Removes the drop-in (one admin prompt) and `~/.dreamcontext/handsfree-mac`. | `uninstall()` |

The CLI calls the running desktop app (`~/.dreamcontext/handsfree-mac/server.json`); with the app closed it says so. In the app: the sheet's Mac panel (setup, Start, "QR'ı göster", battery, devices + "Hepsini çıkar", Dönüş), the chrome chip **Telefonda**, and Settings → Hands-free → fixed address.

**Projects.** Start names the projects the phone may open (the app's checklist, current project pre-checked; the CLI's `--project`). The phone lists and reaches only those: `/api/vaults` and the live chats are filtered, a request or chat socket naming another project is 403 `phone_unavailable`, a request naming none runs on the one chosen project (400 `phone_vault_required` when several are chosen), and a conversation id from another project is refused on every route that takes one (`transcriptOwnerCheck` in `src/lib/transcript-locate.ts`: the transcript's launch dir decides, a worktree counts as its project's). Changing the set = Return + start. This scopes what the APP shows; it is not a sandbox: a bypass chat in a chosen project can still read any folder on the Mac.

**Trust model (what to tell the owner).** A phone socket is NEVER loopback, although cloudflared dials it from 127.0.0.1 (`src/server/phone-origin.ts`). A signed-in phone reaches the whole dashboard API except a laptop-only deny list; the audit table is `ROUTE_POLICY` in `src/lib/handsfree/mac/route-policy.ts` (every registered route: allow or deny, why, what body it may send, which project it acts on), and a route with no row is refused, so a new route never reaches the phone silently. Denied: Settings, the launcher, Mac-mode administration, windows, the Assistant, installers, secrets, sign-ins, voice, Finder/Terminal. Only the chat WebSocket upgrades, only the tunnel's own Origin, never a cross-site request (`Sec-Fetch-Site`), always `nosniff`, only a Mac device session (`~/.dreamcontext/handsfree-mac`). The main listener refuses any request or upgrade carrying a Cloudflare header, so a tunnel pointed at the wrong port reaches nothing. Residual risks: a leaked passphrase or QR is control of the whole Mac while on (bypass-mode chats included); Cloudflare terminates TLS; a quick-tunnel restart changes the address.

**Installed app and notifications.** On the fixed address the phone can add the page to its Home Screen (manifest + icons; iOS keeps the installed app's sign-in apart from Safari's, so it asks for the passphrase once). The chat drawer offers "Turn on notifications" inside the installed app. The Mac then pushes (Web Push, VAPID keys and subscriptions 0600 in `~/.dreamcontext/handsfree-mac`) on exactly three events of a chosen project's chat: a question, a permission request (tool name only), a finished turn (not one the owner interrupted). A tap opens that chat. No push for the chat that phone shows on screen, none after logout, revoke or Return. A quick address cannot carry notifications (it changes every start).

**One chat, two screens.** Only one screen drives a chat. An explicit tap (drawer "Mac'te açık", "Buraya al") takes it and the other screen gets close code 4409 and shows "Buraya al"; automatic reconnects and reload restores are passive (`reattach=passive`) and never take a chat from a live screen. A phone whose network dropped silently is detected by a ping probe (`HOLDER_PROBE_MS`).

**Refusals.** `mac_not_setup`, `mac_sudo_missing` (run setup again), `mac_tunnel_failed` / `mac_probe_failed` (nothing was left running), `mac_admin_cancelled`. At ≤15% battery and discharging the Mac is allowed to sleep again (no re-arm). A crash leaves nothing open: the next app start kills the orphan cloudflared (only if it is ours), signs phones out and restores power; a watchdog also ends cloudflared within seconds of the server dying.

**Heat (the thermal governor).** A lid-closed Mac under full load heats with nothing to stop it, so while Mac mode is on the governor reads macOS `thermalState` every 20 s (no sudo). Nothing is ever killed or quit. At `fair` it moves the owner's own processes burning ≥ 50% CPU (≥ 15% at `serious`/`critical`, older than 20 s) to the efficiency cores with `taskpolicy -b`; children born under them are tracked too. After 6 nominal readings in a row (2 min), or 6 unreadable ones, everything goes back with `taskpolicy -B`, parents before children. Never slowed: claude chats, the dashboard server and the app above it, our cloudflared, and WebKit's XPC services. The phone chip says **Mac serinletiliyor** and the Mac panel **Mac ısındı · N iş yavaşlatıldı**; every clamp and release is logged to `~/.dreamcontext/handsfree-mac/thermal.log`. Return restores sleep and Low Power Mode first, then releases; whatever a quit could not release in time (800 ms) waits in `thermal-pending.json` and is released at the next app start. Accepted risks: a slowed test run can exceed Claude's Bash tool timeout while hot; browsers and emulators feel slow while hot; Safari tabs are spared with the WebKit exemption; `ps` %CPU is a decaying average; an MCP server under a claude can be slowed if it burns ≥ 15%; a child re-parented to launchd before the next tick escapes tracking; after a crash, or a quit past its release deadline, processes stay slowed until the app next opens (sleep and LPM are restored first regardless).
